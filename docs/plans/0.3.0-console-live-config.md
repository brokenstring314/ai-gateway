# 0.3.0 计划：管理控制台 + 实时配置

> 状态：**已立项（2026-10-27，用户要求）**，等待两个决策点确认后开工（见 §9）。
> 本计划推翻 PLAN.md §8 中“不做热重载/配置写 API”“不做完整 Dashboard”两条：
> 网关的核心用途就是**在控制台里方便地添加、管理各渠道的模型，再生成自己的 key / 模型名对外提供**。

## 1. 目标（做完是什么样）

管理员只需启动一次网关（最小 YAML：端口、数据目录、管理员凭证），之后全部在浏览器控制台里完成：

1. **添加渠道**：选预设（DeepSeek、OpenAI、OpenRouter、Ollama…）或自定义 OpenAI 兼容地址，填一个或多个上游 key，点“测试连通性”，点“拉取模型列表”。
2. **发布模型**：把渠道里的上游模型发布成对外模型名（如 `ds-chat` → DeepSeek `deepseek-chat`），可多渠道绑定同一个对外模型，选路由策略（优先级 fallback / 加权负载均衡）。
3. **配置模型元数据**：上下文窗口、最大输出、输入类型（文本/图片/音频/视频/PDF）、结构化输出、工具调用、联网搜索、系统消息支持、推理等级及参数映射、价格。
4. **发 key**：给别人生成 key，限定可用模型、额度（token 或金额）、RPM/TPM、过期时间、IP 白名单。
5. **看用量**：按 key / 模型 / 渠道看请求数、token、费用、错误率、延迟，查请求日志。
6. **以上所有修改即时生效，不重启，不中断进行中的请求**；每次变更有版本记录，可一键回滚。

## 2. 当前差距（基于 master 8b34379）

| 能力 | 现状 |
|---|---|
| 渠道/模型增删改 | 只能改 YAML 后重启；控制台“配置”页只读；`/admin/config/reload` 等返回 410 |
| 实时生效 | 无；`assembleGateway()` 只在启动时构建一次 |
| 按模型路由 | chat 不读 `targets[].models`，模型可能发到不支持它的渠道 |
| 模型元数据 | 无；capabilities 硬编码在 `providers/capabilities.ts`，按 provider 而非按模型 |
| key 策略 | 只有 scopes + 过期；不能限模型、不能设额度；rate-limit 插件是全局每 key 同一值 |
| `/v1/models` | 只返回 id/object/created/owned_by，且不按 key 过滤 |
| 上游 key 存储 | 明文在 YAML / 环境变量 |
| 控制台 | 464 行原生 JS，4 页（概览/密钥/日志/只读配置） |

## 3. 核心设计

### 3.1 配置来源：分两层

- **启动配置（YAML，不变）**：server、auth（管理员）、CORS、可观测性、数据目录、MCP 服务器。改这些仍需重启。
- **运行时资源（SQLite，可在线修改）**：渠道、模型、路由、别名、key 策略、插件参数。控制台和 Admin API 写这里。
- **迁移**：首次以 0.3.0 启动时，若库里没有渠道，把 YAML 里的 `targets` / `strategy` / `aliases` / 插件配置**一次性导入**到库，并在日志提示“以后请在控制台修改”。之后 YAML 中这些段落被忽略并给出警告（可用 `ai-gateway import --force` 再导入）。
- **声明式模式（可选）**：`runtimeConfig.source: file` 时保持 0.2.0 行为（只读、来自文件），给偏好 GitOps 的部署用。默认 `database`。

### 3.2 运行时快照与原子切换

- 把 `assembleGateway()` 的产物封装成不可变 `RuntimeSnapshot`（registry、strategy、executor、pipeline、插件、模型表、key 策略缓存）。
- 每个请求开始时取一次当前快照引用，全程使用；变更时构建新快照 → 校验 → `this.snapshot = next` 原子替换。进行中的请求（含流）继续用旧快照直到结束。
- 熔断器、并发限制器、rate-limit 计数、预算预留按渠道/key 的**稳定 ID** 从旧快照迁移，不因改配置而清零；被删除的渠道其状态随旧快照回收。
- MCP 连接不在快照内（启动配置），避免每次改模型都重连。
- 变更写库在一个事务里：写资源 → 写版本快照（整份 JSON）→ 构建新运行时；构建失败则回滚事务，返回 422 并附错误详情。

### 3.3 数据模型（新迁移）

- `channels`：id、name、preset、base_url、enabled、priority、weight、tags、retry/breaker/concurrency JSON、创建/更新时间。
- `channel_keys`：id、channel_id、**加密后的上游 key**、enabled、状态（ok/失效/限额）、最后错误。一个渠道多个 key 轮询；某个 key 401/402 自动禁用。
- `models`：对外名、显示名、描述、enabled、元数据 JSON（§3.4）、价格（输入/输出/缓存命中，每百万 token，USD）、路由策略。
- `model_bindings`：model_id、channel_id、上游模型名、优先级、权重、参数覆盖 JSON。
- `api_keys` 扩展：allowed_models（空=全部）、额度类型与上限、已用、RPM/TPM、IP 白名单、分组。
- `config_versions`：版本号、时间、操作者 key id、变更摘要、完整快照 JSON（用于回滚）。
- `audit_log`：谁在何时对什么资源做了什么。

### 3.4 模型元数据（回答 10-19 截图里的各项）

每个对外模型可配置：`contextWindow`、`maxOutputTokens`、`inputModalities`（text/image/audio/video/pdf）、`structuredOutput`（none/json_object/json_schema）、`tools`、`parallelTools`、`webSearch`、`systemMessage`（支持/映射为 user/不支持）、`developerRole`（透传/映射为 system）、`reasoning`（不支持/开关/等级列表 + 参数映射，例如 `reasoning_effort: high` → 上游 `thinking: {type: enabled}`）、`logprobs`。

作用：
1. **请求前校验/改写**：超出 `maxOutputTokens` 截断或拒绝；不支持的 content part（如给纯文本模型发图片）按 `compatibility` 策略 warn/drop/reject；developer→system、推理参数映射在这里做。取代硬编码 capabilities（硬编码表降级为“预设默认值”）。
2. **对外暴露**：`/v1/models` 按调用 key 过滤，并在每个条目里附加元数据（扩展字段，OpenAI SDK 会忽略未知字段）。
3. **预设填充**：选 DeepSeek 等预设并拉取模型列表时，自动填入已知模型的默认元数据，管理员可改。

### 3.5 路由

- 请求的 `model` 先按 key 的 allowed_models 检查（403），再解析对外模型 → 取其 bindings → 按模型策略在这些渠道间路由（fallback 按优先级 / loadbalance 按权重），只会发到绑定了该模型的渠道。**这同时修掉“chat 不按 models 列表过滤”的遗留问题。**
- 现有全局 `strategy`（single/fallback/loadbalance/conditional）保留为“未发布为模型的请求”的兜底，可在设置里关闭（关闭则未知模型 404）。

### 3.6 key 额度与计费

- 用量按模型价格计算费用（usage 已有，含流式估算）；请求前检查剩余额度，预留 → 结算（沿用 budget 插件的预留/结算机制，迁到 key 维度）。
- RPM/TPM 按 key 单独设，未设则用全局 rate-limit 插件值。

### 3.7 安全

- 上游 key 用 AES-256-GCM 加密存库，主密钥来自 `GATEWAY_SECRET_KEY`（production 下未设置则拒绝启动）；Admin API 和控制台**永不返回明文**，只显示 `sk-…abcd`。
- 写操作只允许 admin scope；read_only 可看不可改。所有写操作进审计日志。
- 渠道 base_url 校验（http/https、可选禁止内网地址的 SSRF 开关，默认允许以支持 Ollama 本地）。
- “测试连通性”“拉取模型”接口限流，防止被当成代理滥用。

## 4. Admin API（新增，全部 `/admin` 下，JSON）

- `GET/POST /channels`、`GET/PATCH/DELETE /channels/:id`、`POST /channels/:id/test`、`POST /channels/:id/fetch-models`、`POST/DELETE /channels/:id/keys[/:keyId]`
- `GET/POST /models`、`GET/PATCH/DELETE /models/:id`、`PUT /models/:id/bindings`
- `PATCH /keys/:id`（扩展：allowed_models、额度、RPM/TPM、IP 白名单）、`POST /keys/:id/reset-usage`
- `GET /usage?groupBy=key|model|channel&from&to`
- `GET/PATCH /settings`（插件参数、兜底策略、别名）
- `GET /config/versions`、`GET /config/versions/:v`、`POST /config/versions/:v/rollback`、`GET /audit`
- `GET /presets`（预设列表与默认模型元数据）
- 所有写接口支持 `If-Match` 版本号做乐观并发，防止两个管理员互相覆盖。

## 5. 控制台

页面：概览（请求量/费用/错误率趋势、渠道健康）· 渠道 · 模型 · 密钥 · 用量 · 日志 · 设置 · 版本与审计。

- 渠道页：列表（状态灯、延迟、余额/错误）、新增向导（选预设 → 填 key → 测试 → 拉模型 → 勾选发布）。
- 模型页：表格 + 编辑抽屉（元数据各项、价格、绑定渠道拖拽排序、权重）。
- 密钥页：创建时选可用模型、额度、过期；创建后一次性显示明文并可复制；查看单 key 用量。
- 每次保存显示“已生效 · 版本 #N”，失败显示校验错误定位到字段。

技术选型见 §9 决策点 2。

## 7. 兼容性与破坏性变更（0.3.0）

- 默认运行时资源来源改为数据库；旧 YAML 首启自动导入，无需手动迁移。
- `targets[].models` 开始真正生效（只路由到声明了该模型的渠道）——可能改变旧部署行为，CHANGELOG 标注。
- 新增必需环境变量 `GATEWAY_SECRET_KEY`（production）。
- 删除 `abtest` 别名（原计划 0.3.0）；插件 `stage`/`type` 字段改为可选并在文档注明无效（或 0.3.0 删除）。

## 8. 风险

- 快照切换的状态迁移最容易出错 → P0 先做、测试最重。
- 控制台工作量最大 → 先保证 Admin API 完整，控制台只是它的界面。
- 加密主密钥丢失则上游 key 不可恢复 → 文档明确，提供 `ai-gateway channels export --decrypt` 备份命令（需本机访问）。

## 9. 待用户确认的决策点

1. **配置来源**：推荐“数据库为主 + YAML 首启导入 + 可选 file 只读模式”（§3.1）。还是希望 YAML 仍为唯一真相、控制台改的是 YAML 文件本身？
2. **控制台技术**：推荐 Preact + Vite 构建，产物嵌入二进制（体积约 50 KB gz，组件化便于维护这么多表单）；或继续无构建的原生 JS（零依赖，但页面多了会难维护）。
