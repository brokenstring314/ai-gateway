# 0.3.0 计划：管理控制台 + 实时配置

> 状态：**已立项（2026-10-27，用户要求）**；技术栈已定（§9，原则：在实现基本功能的前提下安全、稳定优先，同时保持性能）。
> 本计划推翻 PLAN.md §8 中“不做热重载/配置写 API”“不做完整 Dashboard”两条：
> 网关的核心用途就是**在控制台里方便地添加、管理各渠道的模型，再生成自己的 key / 模型名对外提供**。
> **用户规则（2026-11-02，硬性）：本网关不是收费的 API 服务。** 没有价格、模型定价、费用计算、金额额度、支付、计费或用户账号；只有一个所有者/管理员。所有者偶尔把一两个 key 交给别人并设简单限额，这些人没有账号；key 额度用完就停（不自动恢复，管理员可调高额度或手动清零）。不做分组、不做 IP 白名单。

## 1. 目标（做完是什么样）

管理员只需启动一次网关（最小 YAML：端口、数据目录、管理员凭证），之后全部在浏览器控制台里完成：

1. **添加渠道**：选预设（DeepSeek、OpenAI、OpenRouter、Ollama…）或自定义 OpenAI 兼容地址，填一个或多个上游 key，点“测试连通性”，点“拉取模型列表”。
2. **发布模型**：把渠道里的上游模型发布成对外模型名（如 `ds-chat` → DeepSeek `deepseek-chat`），可多渠道绑定同一个对外模型，选路由策略（优先级 fallback / 加权负载均衡）。
3. **配置模型元数据**：上下文窗口、最大输出、输入类型（文本/图片/音频/视频/PDF）、结构化输出、工具调用、联网搜索、系统消息支持、推理等级及参数映射。
4. **发 key**：给别人生成 key，限定可用模型、token 额度、RPM/TPM、过期时间。
5. **看用量**：按 key / 模型 / 渠道看请求数、token（输入/输出/缓存命中/推理）、错误数、延迟，查请求日志。
6. **以上所有修改即时生效，不重启，不中断进行中的请求**；每次变更有版本记录，可一键回滚。

## 1.5 与原项目的关系

Go 原版 ferro-labs/ai-gateway 已有：嵌入二进制的运维控制台（概览、分析、Providers、路由、插件、Playground、Tracing、请求日志、审计、配置历史/回滚、分作用域 API key）和配置存储（`CONFIG_STORE_DSN`）+ 热重载/回滚 API。**0.2.0 重构时我们把热重载、配置写 API 和完整控制台砍掉了，这是方向性失误**，本计划把它们加回来并扩展。
原版不做的部分（本计划新增）：上游 key 存在 `${VAR}` 环境变量里、不能在控制台填写；没有“渠道 → 对外模型名”的发布与按模型元数据；key 不能限模型/设额度（原版只有 per-key budget 插件）。这部分参考 one-api/new-api 的“渠道”模式。

## 3. 核心设计

### 3.1 配置来源：分两层

- **启动配置（YAML，不变）**：server、auth（管理员）、CORS、可观测性、数据目录、MCP 服务器。改这些仍需重启。
- **运行时资源（SQLite，可在线修改）**：渠道、模型、路由、别名、key 策略、插件参数。控制台和 Admin API 写这里。
- **迁移**：首次以 0.3.0 启动时，若库里没有渠道，把 YAML 里的 `targets` / `strategy` / `aliases` / 插件配置**一次性导入**到库，并在日志提示“以后请在控制台修改”。之后 YAML 中这些段落被忽略并给出警告（可用 `ai-gateway import --force` 再导入）。
- **声明式模式（可选）**：`runtimeConfig.source: file` 时保持 0.2.0 行为（只读、来自文件），给偏好 GitOps 的部署用。默认 `database`。

### 3.2 运行时快照与原子切换

- 把 `assembleGateway()` 的产物封装成不可变 `RuntimeSnapshot`（registry、strategy、executor、pipeline、插件、模型表、key 策略缓存）。
- 每个请求开始时取一次当前快照引用，全程使用；变更时构建新快照 → 校验 → `this.snapshot = next` 原子替换。进行中的请求（含流）继续用旧快照直到结束。
- 熔断器、并发限制器、rate-limit 计数按渠道/key 的**稳定 ID** 从旧快照迁移（P5 起 key 的额度/RPM/TPM 计数器挂在 Gateway 上，根本不在快照里），不因改配置而清零；被删除的渠道其状态随旧快照回收。
- MCP 连接不在快照内（启动配置），避免每次改模型都重连。
- 变更写库在一个事务里：写资源 → 写版本快照（整份 JSON）→ 构建新运行时；构建失败则回滚事务，返回 422 并附错误详情。

### 3.3 数据模型（新迁移）

- `channels`：id、name、preset、base_url、enabled、priority、weight、tags、retry/breaker/concurrency JSON、创建/更新时间。
- `channel_keys`：id、channel_id、**加密后的上游 key**、enabled、状态（ok/失效/限额）、最后错误。一个渠道多个 key 轮询；某个 key 401/402 自动禁用。
- `models`：对外名、显示名、描述、enabled、元数据 JSON（§3.4）、路由策略。（不存价格：2026-11-02 用户决定，P5 迁移删除了未使用的 `pricing_json` 列。）
- `model_bindings`：model_id、channel_id、上游模型名、优先级、权重、参数覆盖 JSON。
- `api_keys` 扩展：allowed_models（空=全部）、token 额度（quota_tokens）、已用（used_tokens）、RPM/TPM、usage_reset_at、revision。
- `config_versions`：版本号、时间、操作者 key id、变更摘要、完整快照 JSON（用于回滚）。
- `audit_log`：谁在何时对什么资源做了什么。

### 3.4 模型元数据（回答 10-19 截图里的各项）

每个对外模型可配置：`contextWindow`、`maxOutputTokens`、`inputModalities`（text/image/audio/video/pdf）、`structuredOutput`（none/json_object/json_schema）、`tools`、`parallelTools`、`webSearch`、`systemMessage`（支持/映射为 user/不支持）、`developerRole`（透传/映射为 system）、`reasoning`（不支持/开关/等级列表 + 参数映射，例如 `reasoning_effort: high` → 上游 `thinking: {type: enabled}`）、`logprobs`。

作用：
1. **请求前校验/改写**：超出 `maxOutputTokens` 截断或拒绝；不支持的 content part（如给纯文本模型发图片）按 `compatibility` 策略 warn/drop/reject；developer→system、推理参数映射在这里做。取代硬编码 capabilities（硬编码表降级为“预设默认值”）。
2. **对外暴露**：`/v1/models` 按调用 key 过滤，并在每个条目里附加元数据（扩展字段，OpenAI SDK 会忽略未知字段）。
3. **预设填充**：选 DeepSeek 等预设并拉取模型列表时，自动填入已知模型的默认元数据，管理员可改。

### 3.5 路由

- 请求的 `model` 先按 key 的 allowed_models 检查（403），再解析对外模型 → 取其 bindings → 按模型策略在这些渠道间路由（fallback 按优先级 / loadbalance 按权重），只会发到绑定了该模型的渠道。**这同时修掉“chat 不按 models 列表过滤”的遗留问题。**
- ~~全局 `strategy` 兜底未发布模型~~：用户 2026-11-01 决定不兜底，未发布模型一律 404 并说明原因。全局 `strategy` 只在未写 `models:` 时、对 `targets[].models` 派生出的模型排序。

### 3.6 key 额度与用量（P5，2026-11-02 用户决定）

- **没有钱**：不定价、不算费用、没有金额额度。删除 budget 插件、target 的 `costPer1k*Tokens`、`ai_gateway_request_cost_usd` 指标、上游 `usage.cost` 透传；仍引用它们的配置校验失败并提示“removed in 0.3.0”。
- **token 额度**（`quotaTokens`，null = 不限）：请求开始前若已用 ≥ 额度 → `403 quota_exhausted`（不用 429：额度不会自动恢复，客户端不应重试）。已放行的请求**一定完整结束**，流不会因额度被中途切断；结束后再把 token（上游 usage，没有就估算）计入，所以最后的请求以及当时在途的并发请求可能超出额度。额度不自动重置：管理员调高额度或 `POST /admin/keys/:id/reset-usage`。图片生成和透传路由无法按 token 计量，有额度的 key 在那里返回 `403 quota_not_metered`。
- **RPM/TPM** 按 key 单独设，未设则用全局 rate-limit 插件值（插件新增 `maxTokensPerMinute`）；超限 `429 rate_limit_exceeded` + `Retry-After`。
- **性能**：额度、RPM、TPM 只读内存计数器（`src/usage/key-meter.ts`，挂在 Gateway 上，不随快照切换清零）；已用 token 约每秒异步批量写回密钥库、关闭时写回、启动时恢复。
- **用量统计**：每个结束的请求累加到按 UTC 小时 × key × 模型 × 渠道的汇总（`usage.sqlite`，WAL，批量写）；`GET /admin/usage?groupBy=key|model|channel&from&to&tz&daily` 汇总，日期按 `tz` 的自然日（默认 UTC）。

### 3.7 安全

- 上游 key 用 AES-256-GCM 加密存库，主密钥来自 `GATEWAY_SECRET_KEY`（production 下未设置则拒绝启动）；Admin API 和控制台**永不返回明文**，只显示 `sk-…abcd`。
- 写操作只允许 admin scope；read_only 可看不可改。所有写操作进审计日志。
- 渠道 base_url 校验：**用户决定（2026-11-02）通过 Admin API 写入的 base_url 只允许公网**——回环、内网（10/8、172.16/12、192.168/16）、链路本地含云元数据 169.254.169.254、CGNAT、保留段、对应 IPv6（::1、fc00::/7、fe80::/10、IPv4 映射/NAT64/6to4 等）以及解析到这些地址的域名一律拒绝，每次请求上游前按 DNS 结果复查（防 DNS 重绑定）、不跟随重定向；暂不提供“允许内网”开关。配置文件里的渠道属运维方可信配置，不受此限（Ollama 等本地服务暂时只能写在配置文件里）。见 §10 路线图。
- “测试连通性”“拉取模型”接口限流，防止被当成代理滥用。

## 4. Admin API（新增，全部 `/admin` 下，JSON）

- `GET/POST /channels`、`GET/PATCH/DELETE /channels/:id`、`POST /channels/:id/test`、`POST /channels/:id/fetch-models`、`POST/DELETE /channels/:id/keys[/:keyId]`
- `GET/POST /models`、`GET/PATCH/DELETE /models/:id`、`PUT /models/:id/bindings`
- `PATCH /keys/:id`（allowed_models、token 额度、RPM/TPM、过期时间；If-Match）、`POST /keys/:id/reset-usage`
- `GET /usage?groupBy=key|model|channel&from&to&tz&daily`
- `GET/PATCH /settings`（插件参数、兜底策略、别名）
- `GET /config/versions`、`GET /config/versions/:v`、`POST /config/versions/:v/rollback`、`GET /audit`
- `GET /presets`（预设列表与默认模型元数据）
- 所有写接口支持 `If-Match` 版本号做乐观并发，防止两个管理员互相覆盖。

## 5. 控制台

页面：概览（请求量/token/错误率趋势、渠道健康）· 渠道 · 模型 · 密钥 · 用量 · 日志 · Playground（走真实路由试调任意对外模型，同原版）· 设置 · 版本与审计。

- 渠道页：列表（状态灯、延迟、余额/错误）、新增向导（选预设 → 填 key → 测试 → 拉模型 → 勾选发布）。
- 模型页：表格 + 编辑抽屉（元数据各项、绑定渠道拖拽排序、权重）。
- 密钥页：创建时选可用模型、token 额度、RPM/TPM、过期；创建后一次性显示明文并可复制；查看单 key 用量、清零用量。
- 每次保存显示“已生效 · 版本 #N”，失败显示校验错误定位到字段。

技术选型见 §9 决策点 2。实现说明（P6）：会话只存进程内存（重启需重新登录，无数据库读）；“已生效 · 版本 #N”取自写响应的 `X-Config-Version`；密钥写操作不进配置版本，显示“已保存”。

## 7. 兼容性与破坏性变更（0.3.0）

- 默认运行时资源来源改为数据库；旧 YAML 首启自动导入，无需手动迁移。
- `targets[].models` 开始真正生效（只路由到声明了该模型的渠道）——可能改变旧部署行为，CHANGELOG 标注。
- 新增必需环境变量 `GATEWAY_SECRET_KEY`（production）。
- 删除 `abtest` 别名（原计划 0.3.0）；插件 `stage`/`type` 字段改为可选并在文档注明无效（或 0.3.0 删除）。

## 8. 风险

- 快照切换的状态迁移最容易出错 → P0 先做、测试最重。
- 控制台工作量最大 → 先保证 Admin API 完整，控制台只是它的界面。
- 加密主密钥丢失则上游 key 不可恢复 → 文档明确，提供 `ai-gateway channels export --decrypt` 备份命令（需本机访问）。

## 9. 技术栈决定（2026-10-27）

用户原则：**基本功能做全，在此基础上最安全、最稳定，同时保持性能。** 据此：

### 9.1 运行时：不换
Bun + Hono + Zod + `bun:sqlite` 保持不变。现有 1378 单测 / 55 e2e、fuzz 与压测（p99 网关开销约 1.7 ms）都建立在这套上，换栈是最大的不稳定来源。**不新增运行时依赖**：加密用内置 WebCrypto（AES-256-GCM + HKDF），密码学不手写。

### 9.2 配置来源：SQLite 为主，YAML 首启导入
- SQLite 事务保证“写资源 + 写版本 + 构建新运行时”要么全成要么全不成，比改写 YAML 文件（并发写、半写入、注释丢失）稳定。
- 每次变更前自动做在线备份（`VACUUM INTO`，保留最近 N 份）；迁移前强制备份；迁移失败拒绝启动而不是带病运行。
- 保留 `runtimeConfig.source: file` 只读模式给 GitOps 部署。

### 9.3 控制台：Preact + Vite，构建产物嵌入二进制
- **安全**：JSX 默认转义输出，从根上消除手写 `innerHTML` 的 XSS；严格 CSP（`script-src 'self'`，无 inline、无 eval、无第三方 CDN），`frame-ancestors 'none'`。
- **依赖面最小**：运行时只有 preact（约 4 KB）+ 一个小型路由；不引 UI 组件库。前端依赖全部锁版本（`bun.lock`），CI 跑 `bun audit` + 依赖许可检查；构建产物带内容哈希，和二进制一起发布，不在运行时拉任何东西。
- **稳定**：组件化 + TypeScript 类型共享（Admin API 的 Zod schema 生成前端类型），表单校验与后端同一份 schema。
- 构建只在开发/CI 发生，运行时不需要 Node/Vite。

### 9.4 控制台认证改为会话 Cookie
现状把 admin key 放在 `sessionStorage`，一旦有 XSS 就能被读走。改为：登录时用 admin key 换取服务端会话，`HttpOnly; Secure; SameSite=Strict` Cookie，短时效（默认 12h，可配）+ 空闲超时；所有写请求要求 CSRF token（双提交）；登录失败限流与锁定；会话可在控制台里列出和吊销。API 客户端仍可用 Bearer key。

### 9.5 安全清单（每阶段验收必过）
- 上游 key 加密存储，主密钥 `GATEWAY_SECRET_KEY`；永不在 API/日志/审计/版本快照中出现明文（版本快照只存密文引用）。
- 所有 Admin 写接口：Zod 严格校验、admin scope、CSRF、审计、乐观并发。
- 渠道 base_url 的 SSRF 防护：Admin API 写入的地址只允许公网（2026-11-02 用户决定，见 §3.7）；本地/局域网模型服务的显式开关列入 §10 路线图。
- “测试连通性/拉取模型”限流、超时、响应大小上限。
- 每阶段跑一轮针对新代码的安全审计（沿用前三轮 bug hunt 方式），高危清零才进入下一阶段。

### 9.6 稳定性保障
- 原子快照切换 + 状态迁移；进行中的请求/流永远不受配置变更影响（专门的并发测试：持续流量下连续改配置 1000 次，零错误、零泄漏）。
- 新快照构建失败 → 事务回滚，旧配置继续服务；一键回滚到任一历史版本。
- 配置 fuzz 扩展到 Admin API（随机变更序列），SSE fuzz、压测作为每阶段回归。
- 渠道级健康：key 失效自动禁用并告警到控制台，不影响其他渠道。

### 9.7 性能保障
- 热路径零数据库读：路由、模型表、key 策略全在内存快照里；key 校验结果缓存（吊销时随快照失效）。
- 用量汇总与已用 token 异步批量写库（WAL），额度/RPM/TPM 检查只读内存计数器，约每秒落盘；进程重启从库恢复。
- 控制台静态资源 gzip/brotli 预压缩、长缓存；统计接口走预聚合表，不扫请求日志全表。
- 验收门槛：在现有压测脚本上，开启全部新功能后网关 p99 开销仍 < 5 ms（PLAN 约束 6），吞吐下降不超过 10%。

## 10. 路线图（0.3.0 之后）

- **本地/局域网模型服务（Ollama、vLLM 等）的显式开关**（2026-11-02 记录）：P4 按用户决定只允许 Admin API 写入公网 base_url。以后增加一个默认关闭、需管理员显式开启的选项（例如按 CIDR/主机名白名单），开启后允许指定的内网地址，云元数据地址（169.254.169.254 等）始终拒绝，并在审计与控制台中明确标出。
